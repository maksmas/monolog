# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Monolog is a CLI personal backlog tool written in Go. Tasks are stored as individual JSON files in a git repo for conflict-free cross-device sync. See `docs/plans/completed/20260411-monolog-cli-mvp.md` for the MVP spec.

## Build & Test Commands

```bash
go build -o monolog          # Build binary
go test ./...                # Run all tests
go test ./internal/store/    # Run tests for a single package
go test -run TestCreate ./internal/store/  # Run a single test
go vet ./...                 # Lint
```

### Release & distribution

```bash
make build VERSION=v0.1.0    # build with an explicit version stamped in
make demo                    # regenerate the README hero GIF (needs vhs)
```

- **Versioning**: `cmd.Version` (default `"dev"`, wired into cobra's `Version:` so `monolog --version` works) is injected at build time via the Makefile's `LDFLAGS` (`-X github.com/mmaksmas/monolog/cmd.Version=$(VERSION)`, `VERSION ?= dev`). `build` and `build-bot-linux-arm64` share the same ldflags.
- **Releases**: cut by pushing a `v*` git tag, which triggers `.github/workflows/release.yml` → GoReleaser (`.goreleaser.yaml`, `version: 2` schema). GoReleaser cross-compiles darwin+linux × amd64+arm64 archives + `checksums.txt` onto a GitHub Release, and publishes a Homebrew **cask** (`homebrew_casks:` block) to the `mmaksmas/homebrew-tap` repo (requires the `HOMEBREW_TAP_GITHUB_TOKEN` Actions secret). macOS users install with `brew install mmaksmas/tap/monolog` — the cask is **macOS-only** (Homebrew casks are unsupported on Linux, and this one runs a macOS `xattr` quarantine hook); Linux users take the prebuilt binary or `go install`.
- **Demo GIF**: the README hero (`docs/img/demo.gif`) is generated from `docs/demo.tape` via `make demo` (requires charmbracelet `vhs`). The tape isolates `MONOLOG_DIR` to a temp dir so a real backlog is never recorded; the rendered GIF is committed as a binary artifact.
- **CI**: `.github/workflows/ci.yml` runs `go build`/`test`/`vet` on push + PR (Go version pinned via `go-version-file: go.mod`).

## Architecture

```
main.go                 → Entrypoint, calls cobra root command
cmd/                    → One file per CLI command (add.go, ls.go, etc.)
internal/config/        → User-facing date-format and theme accessors; Load/Save/SetDateFormat for settings persistence
internal/model/task.go  → Task struct with JSON tags, ULID generation
internal/store/         → File-based CRUD, prefix-match ID lookup, initials resolution, filtering/sorting
internal/ordering/      → Fractional position math and rebalancing
internal/schedule/      → Bucket names ↔ ISO dates, bucket classification, layout-aware Parse/FormatDisplay
internal/recurrence/    → Recurrence-rule parsing, next-occurrence math, shared done+spawn flow
internal/display/       → Terminal table formatting and compact date helpers (layout-aware)
internal/git/           → Git operations (init, auto-commit, sync with conflict resolution); also AutoCommitSHA (stage+commit+return HEAD SHA), headSHA, CommitSubject, Revert, RevertSHA helpers used by TUI undo/redo
internal/tui/           → Bubble Tea interactive TUI (default when run with no subcommand)
internal/email/         → Gmail integration: small Gmail interface + real client, OAuth token I/O & refresh, pure Message→Task conversion, batch-commit Sync orchestrator
internal/telegram/      → Telegram bot integration: neutral Bot interface + real tgbotapi client, pure parse/format helpers, long-poll Serve orchestrator with pull ticker and read-only-on-conflict mode
```

Commands in `cmd/` handle CLI parsing and delegate to `internal/` packages. Running `monolog` with no subcommand launches the interactive TUI. Every mutation auto-commits to git.

## Key Design Decisions

- **One JSON file per task** (`<repo>/.monolog/tasks/<ULID>.json`): eliminates merge conflicts on sync. Two devices editing different tasks rebase cleanly.
- **ULID IDs**: time-sortable, globally unique, users type partial prefixes (e.g. `01J5K`) which resolve via directory scan.
- **Title-initials lookup**: CLI commands (`done`, `edit`, `rm`, `mv`) resolve identifiers via `store.Resolve()`, which tries ULID prefix first, then falls back to matching the first letters of each word in open task titles (e.g. `flb` → "Fix login bug"). Minimum 2 characters, case-insensitive, prefix-matching on initials. Ambiguous matches list conflicting titles. Implemented via `model.Initials()` and `store.Resolve()`.
- **Fractional positions**: inserting between positions 1000 and 2000 gives 1500. Rebalance all positions in a schedule group when any gap drops below 1.0. Default spacing is 1000.
- **Schedule values**: `today` (default), `tomorrow`, `week`, `month`, `someday`, or a date. User-facing input/display format is configurable via `internal/config` (`DateFormat()`, `DateFormatLabel()`, `DateRegex()`); default is `DD-MM-YYYY` (`"02-01-2006"`). `schedule.Parse(input, now, layout)` accepts bucket names, input in the passed layout, and legacy ISO (`2006-01-02`) silently so pre-existing scripts keep working. `schedule.FormatDisplay(iso, layout)` renders a stored ISO date back to the configured layout at display time. On-disk `schedule` JSON stays ISO regardless of `DateFormat` — no migration when the display format changes. Callers pass `config.DateFormat()` through to `schedule`/`display`/`model` helpers; those packages never import `internal/config` directly, which keeps them easy to test with arbitrary layouts. **Relative shorthands** (`Nd`, `Nw`, `Nm` — e.g. `3d`, `2w`, `1m`) are handled by `schedule.ParseRelative(input string, now time.Time) (string, bool)`, which the TUI `updateReschedule` calls before `schedule.Parse`; on a match it returns an ISO date directly without touching `schedule.Parse`'s signature or behavior.
- **Runtime data directory**: `~/.monolog/` by default, override with `MONOLOG_DIR` env var.
- **Active tasks**: the reserved `active` tag marks tasks in the current working set. Active tasks render in green in the TUI and appear in a dedicated panel above the tab bar. `done` auto-deactivates; `edit --tags` preserves active state.
- **Auto-tag from title prefix**: when creating a task, if the title starts with `"tagname: ..."` and `tagname` is a tag that already exists on another task, it is automatically added as a tag. Title is kept as-is. The reserved `active` tag is excluded. Implemented via `model.ParseTitleTag()` and `model.CollectTags()`.
- **Tag view mode**: the TUI has two view modes (`viewSchedule` / `viewTag`), toggled with `v`. In tag view, tabs become tags (active first, alphabetical middle, untagged last), each showing tasks grouped by schedule bucket with separator items. Grab mode in tag view restricts movement to within a single tag tab (no left/right). Launch directly into tag view with `monolog --tags` / `-T`.
- **CompletedAt lifecycle**: `Task.CompletedAt` (RFC3339, omitempty) is set when `doneSelected()` fires. It is never cleared (tasks cannot be reopened today). Existing tasks without `CompletedAt` are excluded from avg-time-to-complete calculations. Used by `model.ComputeStats()`.
- **Stats bar**: the TUI always shows a one-line stats bar (total/open/done/in-tab/avg) above the tab bar. Stats are cached in `Model.stats` (a `model.Stats` value) and refreshed via `reloadAllTasks()` at the end of every `reloadAll()` call. `model.ComputeStats([]Task, time.Time)` and `model.FormatDuration(days float64)` in `internal/model/stats.go` are pure functions, easily unit-tested.
- **Tag autocomplete**: both the add-task and retag modals show inline autocomplete suggestions as the user types in the tag field. `model.FilterTags(known, field)` is a pure function that extracts the fragment after the last comma, filters known tags by case-insensitive prefix, excludes already-entered tags, and caps at 5 results. Suggestions are navigated with Up/Down, accepted with Tab/Enter (replaces fragment and appends `", "`), and dismissed with Esc. State lives in `Model.suggestions`/`Model.suggestionIdx`, shared between modals since only one is open at a time. The add modal's Recur field reuses the same suggestion plumbing via the pure `recurrence.Suggest(input)` function and shows a static grammar hint line (`recurrence.GrammarHint`) under the input — on the Recur field only **Tab** accepts a suggestion (replacing the full value, since recurrence is a single value) while **Enter** always submits the modal; the same `GrammarHint` is also prepended as a `#` comment header in the TUI YAML edit buffer and referenced in the `--recur` CLI help on `add`/`edit`.
- **Task notes**: notes are stored as timestamped entries appended to the existing `Body` field using `--- <date> HH:MM:SS ---` separators, where `<date>` is rendered in the configured `config.DateFormat()` (default `DD-MM-YYYY`) — no schema migration needed. A `NoteCount int` field (JSON `note_count`, omitempty) tracks the count for fast badge rendering (`[N]` in the task list) without body parsing. `model.AppendNote(body, text, now, layout)` formats and appends note text; `model.CountNotes(body, dateRegex)` only recognizes separators whose date fragment matches the passed regex. Callers build the regex from `config.DateRegex()`. **No backward compat** on the separator regex: changing the configured format loses the `[N]` count contribution from notes written under the old format (stored text is untouched). `NoteCount` is recalculated from `Body` inside both `Store.Create` and `Store.Update` via `model.CountNotes()` — the store layer is the single source of truth, so any path that writes a task (new or existing, including recurring-task spawns whose body already carries the `Spawned from` note) keeps the count consistent without caller bookkeeping. CLI: `monolog note <id> "text"` adds a note, `monolog show <id>` prints full task detail.
- **Detail panel**: pressing `Enter` in the TUI toggles a right-side panel showing task metadata (title, schedule, tags, dates) and the full body with notes. An inline textarea at the bottom accepts new notes (`Enter` submits, `Alt+Enter` inserts a newline, `Esc` closes the panel). Navigating tasks with `Up/Down` while the panel is open refreshes its content. Panel width is ~45% of the terminal.
- **Fuzzy search**: `/` in TUI normal mode opens a full-screen search overlay that fuzzy-matches across both title and body of all tasks (open and done), powered by `github.com/sahilm/fuzzy`. Title matches are weighted 2x over body matches. Enter commits to the selected task, switching `activeTab` to the target bucket/tag and focusing the task; Esc cancels with no side effects. Pure ranker lives in `internal/tui/search_match.go`; overlay UI in `internal/tui/search.go`.
- **Recurring tasks**: `Task.Recurrence string` (JSON `recurrence,omitempty`) holds a rule in one of four forms — `monthly:N` (1..31, clamped to month-end for short months), `weekly:<day>` (accepts three-letter `mon|tue|...|sun`, full names `monday|...|sunday`, or numeric `1..7` with Mon=1, all case-insensitive), `workdays` (Mon-Fri), or `days:N` (N days after completion). Parsing and next-date math live in `internal/recurrence/` (`Parse(string) (Rule, error)`, `Canonicalize(string) (string, error)`, `Rule.Next(time.Time) time.Time`, `Rule.String()`); `Rule.String()` emits the canonical form (`weekly:mon`, `workdays`) so alias inputs round-trip through edit to canonical storage. All three callers (`cmd/add`, `cmd/edit`, and the TUI add modal / YAML editor) validate-and-normalize through `recurrence.Canonicalize`. Spawn is driven by `recurrence.CompleteAndSpawn(s *store.Store, task *model.Task, now time.Time, w io.Writer, dateFormat string)` (shared by `cmd/done.go` and the TUI `d` key), where `w` receives any spawn-warning messages and `dateFormat` is the configured user-facing layout passed in from `config.DateFormat()`. When a completed task has a non-empty `Recurrence`, a new task is created with a fresh ULID, copied Title/Body/Source/Recurrence, tags minus `active`, `Schedule = Rule.Next(now)` (stored ISO); the old task receives the done-state transition AND the back-reference note in a single `Store.Update`, and both files are committed in one git commit whose message formats the next date with `dateFormat` (e.g. `"done: <title> (recurring, next 25-04-2026)"` under the default). Bidirectional cross-references: the new task gets a `"Spawned from <old-ULID>"` note, the old task gets a `"Spawned follow-up: <new-ULID> (scheduled <date>)"` note formatted in `dateFormat`. Stop semantics are edit-based — clearing `Recurrence` (CLI `--recur ""` or removing the `recurrence:` line in the TUI YAML editor, which now exposes it through `editableFields`) before completing prevents the next spawn; there is no SeriesID or series concept. Any spawn failure (invalid stored rule, list/create error) is warned to the caller's stderr and skipped while the underlying completion still succeeds — the repo is never left with an uncommitted half-spawn. CLI surface: `--recur` flag on `add` and `edit`; TUI surface: a third input `addFocusRecur` in the add modal and a `recurrence` line in the YAML editor. **Visibility**: recurring tasks render a `[↻]` marker in the TUI list-item description line (right after the `[N]` notes badge in `item.Description()`), and the detail panel adds a `Recur: <rule>` line between the `Schedule:` and `Tags:` lines (`Model.detailPanelView`). Both are conditional on `Recurrence != ""`; done recurring tasks keep the marker because the source task retains its rule after spawn.
- **Clickable URLs (TUI)**: the TUI wraps `http://` and `https://` URLs in OSC 8 terminal hyperlink escapes so Cmd/Ctrl-click on a visible URL opens the browser. The pure `display.Linkify(s string) string` helper (`internal/display/links.go`) detects URLs with `https?://\S+`, strips trailing punctuation (`.,;:!?)`) so sentence punctuation stays outside the link, and wraps each match as `\x1b]8;;<URL>\x1b\\<URL>\x1b]8;;\x1b\\`. OSC 8 sequences are zero-width so `lipgloss` column math is unaffected, and styling composes cleanly. Integration points — always applied post-wrap / post-truncate on the final visible fragment so escapes never dangle across a cut: the detail-panel title header, the detail-panel body lines, and the task-list title column. **Contract for new render paths**: any caller applying `display.Linkify` to width-constrained output must first pass the text through the URL-aware pre-processors (`wrapTextPreservingURLs` for wrapping, `truncateTitlePreservingURLs` for truncation, both in `internal/tui/model.go`; `display.FindURLSpans` for custom layout logic) so a URL is never split across the visible fragment — otherwise Linkify's regex would see a truncated match and the OSC 8 target would point at a broken URL. `vlist.itemHeight` must mirror whichever wrap helper the renderer uses so row-height prediction stays aligned with rendered output. `MONOLOG_NO_LINKS=1` is an escape hatch that turns `Linkify` into a no-op (also covered by tests via `t.Setenv`). Terminals without OSC 8 support render URLs as plain text — no regression. CLI output (`monolog show`, `monolog ls`), the fuzzy-search overlay, and the YAML editor intentionally stay plain text.
- **TUI color themes**: named color themes ("default" and "dracula") are selectable via the `"theme"` key in `<MONOLOG_DIR>/.monolog/config.json`; the `MONOLOG_THEME` env var takes precedence over the file. `Theme` struct in `internal/tui/theme.go` holds one `lipgloss.AdaptiveColor` field per color role (chrome: `ActiveBorder`, `ModalBorder`, `Hotkey`, `ActiveTabBg`, `ActiveTabFg`, `TabFg`, `Borders`; task list: `NormalText`, `SelectedText`, `DimText`, `GrabText`, `ActiveNormal`, `ActiveSelected`; search: `SearchDone`, `SearchActive`, `SearchCount`, `SearchMeta`, `SearchPreviewBorder`, `SearchPreviewDim`); the `themes` registry maps names to `Theme` values and unknown names silently fall back to `defaultTheme`. `config.Theme()` in `internal/config/` reads the JSON config file and applies the env-var override. `buildStyles(Theme) tuiStyles` in `tui.go` constructs all lipgloss styles from theme fields (replacing the former package-level `var` block); `initStyles(Theme)` in `model.go` handles task-list item styles; `Model` gains `theme` and `styles` fields used for inline color overrides throughout the render paths. Theme-independent styles (`suggestionBoldStyle`, `suggestionDimStyle`, `searchSelectedStyle`) live as package-level vars in `tui.go`. Both `"theme"` and `"date_format": "02-01-2006"` keys are written by `git.Init` into the initial `config.json` template. **User-authored themes (file-based)**: `internal/tui/theme_load.go` scans `<MONOLOG_DIR>/.monolog/themes/*.json` at startup via `loadUserThemes` and merges them into the package-level `themes` map through `initThemes` — both called from `tui.Run` before the Model is built. Files use snake_case keys (`active_border`, `normal_text`, …) with `{"light": "...", "dark": "..."}` pairs; all 19 fields are required. `bootstrapExampleTheme` creates the themes directory with a single `example.json` (a full dump of `defaultTheme`) the first time the directory is absent — it never overwrites or recreates once the directory exists, so deleting `example.json` is a sticky user choice. Loader rejections (invalid JSON, missing field, empty color value) are printed to stderr with a `monolog:` prefix before Bubble Tea takes over; the TUI continues with whatever loaded cleanly. User files named `default.json` or `dracula.json` are rejected as collisions — built-ins are immutable. If the configured theme name disappears from disk between runs, `newModel` falls back to `defaultTheme` and surfaces `theme "<name>" not found, using default` in the status bar without rewriting `config.json` (restoring the file later brings the selection back automatically). Reload is edit-and-restart — no file watcher.
- **Settings modal**: `,` in normal TUI mode opens a settings overlay (`modeSettings`) backed by `openSettings()` / `updateSettings()` / `applySettings()` in `model.go`. Two rows: date format (DD-MM-YYYY / MM-DD-YYYY / YYYY-MM-DD) and theme. `↑↓` navigate rows; `←→` cycle values; `Enter` saves via `config.SetDateFormat` + `config.Save(repoPath, theme, fmt)` and applies the new theme live by rebuilding `m.theme`/`m.styles`/`m.baseStyles`; `Esc` discards. `config.Load(monologDir string) error` is called in `cmd/helpers.go#openStore` so every command (TUI + CLI) picks up the persisted date format on startup. `config.AllFormats() []FormatInfo` (Layout + Label fields) exposes the ordered format list to the settings UI. `config.Save` does a read-modify-write so unknown config.json keys (e.g. `"default_schedule"`, `"editor"`) are preserved.
- **Undo (TUI)**: `u` / `ctrl+z` in normal mode triggers multi-level undo (last 10 actions) backed by `git revert <sha> --no-edit`. TUI mutations use `git.AutoCommitSHA` (stage+commit+return HEAD SHA) while CLI commands use `git.AutoCommit` (no SHA returned). Every TUI mutation captures the SHA into `Model.undoStack` ([]string, capped at 10, newest last). `undoCmd()` **pops the SHA before launching the goroutine** (prevents a second keypress racing on the same SHA), then calls `git.CommitSubject` to build the status message and `git.RevertSHA` (thin wrapper over `git.Revert` + `headSHA`) to create the revert commit and capture its SHA. `CommitSubject` failure is treated as non-retriable (stale SHA — e.g. after a rebase) and the SHA is dropped. `RevertSHA` failure (e.g. conflict) signals restore via `taskSavedMsg.restoreUndoSHA` so `Update` pushes the SHA back in the main loop — never from inside the goroutine (which would race). Stack is cleared when a sync with a remote completes (rebase may have rewritten SHAs); local-only syncs preserve the stack. Grab-move rebalance positions are not captured in the move commit and thus not reverted by undo (pre-existing limitation of the move commit).
- **Quick capture (Raycast)**: `cmd/add.go` exposes `--body`/`-b` for setting `task.Body` at create time; `Body` was already on the model with `omitempty`, so empty bodies still drop from JSON. The capture flow itself lives entirely outside the Go binary in `docs/raycast/`: a Raycast script command (`monolog-capture.sh`) shells out to `monolog add "$1" --body "$2" --tags inbox`, and a bookmarklet (documented in `docs/raycast/README.md`) builds two prefilled args from `window.getSelection()` + page metadata, redirects to `raycast://script-commands/monolog-capture?arguments=...`. Selection-aware behavior: title prefills with the selection (truncated to 80 chars) or the page title; note prefills with the full selection plus a URL augmented with a `#:~:text=<encoded selection, 300-char cap>` text fragment so reopening scrolls to and highlights the original passage. Same script services the desktop hotkey case (Raycast's "prefill from selected text") with no URL involved. No daemon, no second binary, no URL-scheme registration in monolog itself.
- **Email integration**: opt-in Gmail import + archive-on-done, off until configured. `internal/email/` owns the integration; `cmd/email.go` registers `monolog email {sync,auth,status}`. `internal/email/` MUST NOT import `internal/config` — values flow in via `config.Email() config.EmailConfig` (`{Enabled, Label, SyncInterval, MaxPerSync, ClientSecretsPath}`) read once by callers (TUI Model, `cmd/email.go`, `cmd/done.go`) and passed by value. Config block is the optional `"email"` key in `<MONOLOG_DIR>/.monolog/config.json` (defaults: enabled=false, label=`"monolog"`, interval=5m, max_per_sync=100, client_secrets_path=`$XDG_CONFIG_HOME/monolog/gmail_credentials.json`). `config.SaveEmail` is the read-modify-write writer that preserves foreign keys; `monolog email auth` flips `enabled=true` after a successful OAuth flow. **OAuth**: scope `gmail.modify` (smallest scope covering list/read/label-modify); `Authorize` runs a local `127.0.0.1:0` redirect-callback `http.Server` against the user's downloaded Desktop-app client-secrets JSON; tokens persist as `0600` JSON outside the git repo at `$XDG_CONFIG_HOME/monolog/gmail_token.json` so OAuth secrets never sync across devices. `HTTPClient` wraps a `oauth2.TokenSource` with `persistingTokenSource` so refreshed access tokens get written back to disk. `email.IsAuthMissing(err)` discriminates the no-token case for friendly status output. **Gmail abstraction**: `type Gmail interface { ListLabeled(ctx, label) ([]string, error); Get(ctx, id) (*Message, error); ArchiveLabel(ctx, id) error }` with neutral `Message{ID, Subject, From, Snippet}` DTO so tests fake the interface and the rest of the codebase never imports `google.golang.org/api/gmail/v1`. `realGmail` wraps `*gmail.Service`; `ListLabeled` paginates exhaustively preserving Gmail's newest-first order; `Get` uses `format=METADATA, metadataHeaders=[Subject,From]` (snippet comes for free); `ArchiveLabel` calls `users.messages.modify(removeLabelIds=["INBOX"])` and intentionally keeps the trigger label (option A — archive only). **Conversion** (`convert.go`, pure): `ToTask(*Message, time.Time) (model.Task, error)` strips chained `Re:`/`Fwd:`/`Fw:` prefixes via `(?i)^((re|fwd?|fw):\s*)+`, falls back to `"(no subject)"`; sender via `net/mail.ParseAddress`, falls back to `"unknown"`; snippet HTML-unescaped and rune-capped at 200 with `…` only when truncation occurs; body = `"From: <name>\nhttps://mail.google.com/mail/#all/<msg-id>\n\n<snippet>"` (URL omits `/u/0/` so it works for any signed-in account; no trailing blank lines when snippet empty); tags=`["email"]`; schedule=today; Source=`"gmail"`; SourceID=msg.ID; fresh ULID per call. **Sync** (`sync.go`): `Sync(ctx, gmail, store, repoPath, SyncOptions{Label, MaxPerSync, Now, Writer}) SyncResult{Created, Err}`. Algorithm: (1) `gmail.ListLabeled` (newest-first), (2) build dedup set from `store.List(ListOptions{})` (no Status filter → spans open+done) of SourceIDs where `Source=="gmail"` — completed-and-archived emails self-suppress, (3) filter to new IDs preserving order, (4) take first `MaxPerSync` (remaining silently deferred to next run — soft cap), (5) per-msg Get→ToTask→Store.Create (failures warn-and-continue), (6) **single** `git.AutoCommit(repoPath, "email: imported N task(s) (label=<label>)", files...)` if any created — no commit when zero. **Archive on done**: after `recurrence.CompleteAndSpawn` + `git.AutoCommit`, both `cmd/done.go` (CLI, 5s ctx timeout, fire-and-forget) and TUI `doneSelected` (via `archiveEmailCmd`) call `gmail.ArchiveLabel(ctx, sourceID)` when `task.Source=="gmail"` && `task.SourceID!=""` && email enabled. Archive failure is NON-FATAL: warn-and-continue, task stays done. CLI uses a swappable `var archiveFn = realArchive` seam for testing; TUI swaps via the `Gmail` interface. **TUI integration**: Model gains `emailEnabled`, `emailSyncing`, `emailLabel`, `emailMaxPerSync`, `emailInterval` (no `emailLastErr` — flash messages reuse the existing status-bar mechanism). `Init()` returns `tea.Batch(emailSyncCmd(), emailTickCmd(interval))` when enabled (initial sync IS the first tick); ticker is `tea.Tick`-based and self-rescheduling on every `emailTickMsg`. `s` in `updateNormal` dispatches `tea.Batch(gitSyncCmd, emailSyncCmd())` when enabled. `emailSyncResult{Created, Err}` flashes `"email: N imported"` / `"email sync: <err>"` and calls `reloadAll()` when `Created>0`. `archiveResult{Err}` flashes `"email archived"` / `"archive failed: <err>"`. Status bar shows `↻` while `emailSyncing`. Bottom-bar `s` hint widens to `"sync (git+email)"` when enabled. When email is disabled all email cmds return nil so `tea.Batch` ignores them — the keybinding stays a single git-sync.
- **Telegram integration**: opt-in Telegram bot for mobile capture / browse / done, off until configured. `internal/telegram/` owns the integration; `cmd/telegram.go` registers `monolog telegram {serve,status}`. `internal/telegram/` MUST NOT import `internal/config` — values flow in via `config.Telegram() config.TelegramConfig` (`{Enabled, AllowedUserIDs, PullInterval, BrowseLimit}`) read once by `cmd/telegram.go` and passed by value to `telegram.Serve`. Config block is the optional `"telegram"` key in `<MONOLOG_DIR>/.monolog/config.json` (defaults: enabled=false, allowed_user_ids=nil, pull_interval=30s, browse_limit=20). `config.SaveTelegram` is the read-modify-write writer that preserves foreign keys (mirrors `SaveEmail`). **Secrets**: bot token comes from the `--token` flag on `monolog telegram serve` with fallback to the `MONOLOG_TELEGRAM_TOKEN` env var (flag wins; env is the recommended systemd path because `--token <value>` is visible in `ps aux`); `GIT_SSH_COMMAND` env points git at the EC2-local SSH deploy key. Token is never logged and never printed in `status` output (`status` only prints "set" / "unset"). **Bot abstraction**: `type Bot interface { GetUpdates(ctx, offset, timeout) ([]Update, error); SendMessage(ctx, chatID, html, kb) (msgID int, error); EditMessage(...); AnswerCallback(...) }` with neutral DTOs (`Update`, `Message`, `CallbackQuery`, `InlineButton`, `InlineKeyboard`) so tests fake the interface and the rest of the codebase never imports `github.com/go-telegram-bot-api/telegram-bot-api/v5`. `realBot` wraps `*tgbotapi.BotAPI`; `NewClient(token)` returns the production bot. **Capture** (free text from allow-listed user): `ParseCapture(text)` splits on first `\n` → first line title, rest body; `ParseInlineTags` extracts `#hashtag` tokens from the title (regex `#([A-Za-z0-9_-]+)`, deduped, hashtags stripped + whitespace collapsed). Body and inline `#hashtag` content survives untouched in the body. `store.Create` then applies the existing `tagname: <title>` prefix auto-tag rule against tags already on disk. Default schedule = today. **Browse**: `/today`, `/week`, `/active`, `/all` query `store.List` and send one message per task with inline buttons; `/all` is capped at `BrowseLimit` with a `<i>+N more — open laptop</i>` footer. Empty bucket replies with a single `<b>Today</b> — nothing 🎉` message. **Callbacks** (inline buttons, data format `verb:<ULID>`): `done:` runs `recurrence.CompleteAndSpawn` (writer=io.Discard; spawn warnings logged to opts.Writer) and edits the message to a strike-through row plus `↻ next: <date>` when a follow-up spawned; `active:` toggles the reserved `active` tag (add if absent, remove if present); `view:` swaps the summary into `FormatDetailView` (ID + Schedule + Tags + Recur + Created + Notes + body, 4096-char cap with `… (open laptop for full body)` truncation) with a `[⬆ Collapse]` button; `collapse:` reverses `view:`. ULID is full 26 chars in callback data so resolve is unambiguous; out-of-range / deleted IDs surface a toast (`"task not found"` / `"already done"` / `"invalid"`). **Reply=note**: any Telegram reply to a previously-sent task message extracts the first whitespace-bounded token from the replied-to text as a task prefix, calls `store.Resolve`, appends the reply text via `model.AppendNote`, and commits. Ambiguous prefix surfaces `store.Resolve`'s error verbatim (HTML-escaped). **Access control**: non-allow-listed users are silent-dropped on plain messages; for callbacks the callback is answered with an empty toast (to clear the loading spinner) but no action runs. **Read-only on conflict**: if `git.Sync` fails after a local `git.AutoCommit`, the handler sets an `atomic.Bool` `readOnly` flag — subsequent write attempts (capture, done, active, note) reply with `⚠️ sync conflict, change not saved — resolve on laptop` and do NOT mutate the store; browse commands prepend `⚠️ <i>read-only — sync conflict pending</i>`. The background pull ticker clears the flag on the next successful `PullRebase`. **Sync orchestration** (`telegram.Serve`): startup `PullRebase` (non-fatal), then two goroutines — a `time.Ticker` pull-rebase ticker (interval = `cfg.PullInterval`) and a long-poll update loop calling `bot.GetUpdates(ctx, offset, 30s)`; updates handled inline (single-threaded write path via `sync.Mutex`); `ctx.Done()` shuts both down cleanly. Tests inject `pullFunc`/`syncFunc` to avoid real git operations. **HTML rendering**: all titles/bodies pass through `html.EscapeString` before insertion into HTML templates; the only literal tags are `<code>`, `<i>`, `<s>`, `<b>`. URLs auto-linkify on the Telegram client (no `display.Linkify` OSC 8). **Deployment topology**: long-running `monolog telegram serve` on an EC2 t4g.nano with its own clone of the tasks git repo; long-polling means no public HTTP endpoint and no webhook. `docs/deploy/` ships a systemd unit, `env.example`, and a README walking through EC2 bootstrap (user creation, SSH deploy key, clone, systemd install). `make build-bot-linux-arm64` cross-compiles; `make deploy-bot` scps + restarts via SSH. No webhook, no HTTP listener, outbound HTTPS only. The bot is just another monolog client — laptop side gains nothing new; the existing `s` sync + fsnotify watcher already handle the read side.
- **TUI auto-refresh on external changes**: the running TUI watches `<repo>/.monolog/tasks/` via `fsnotify` (debounced 250ms) and reloads when another process mutates the store — Raycast capture, a second terminal running `monolog add`, or an external `git pull`. `internal/tui/watcher.go` owns a small `taskWatcher` (channel + goroutine) constructed in `tui.Run`; failure to start (missing dir, OS limits) prints `monolog: watcher: <err>` to stderr and runs the TUI without auto-refresh, same precedent as `bootstrapExampleTheme`. `Model.watchCmd()` blocks on the watcher's channel and returns `externalChangeMsg{}`; the `Update` handler calls `reloadAll()` + `recomputeLayout()` and re-arms the cmd. **Reload is idempotent and unfiltered** — events from the TUI's own writes also fire, but `reloadAll()` is cheap and avoiding a race with self-mutations isn't worth the synchronization. No status flash on routine refresh (would be noisy under rapid external edits). `MONOLOG_NO_WATCH=1` is the escape hatch (mirrors `MONOLOG_NO_LINKS=1`); only `Write|Create|Remove|Rename` events trigger reload (chmod-only events are filtered as noise). Watcher is stopped via `defer w.Stop()` in `tui.Run`; the goroutine closes its channel on stop so `watchCmd` returns nil and the loop unwinds.
- **Redo (TUI)**: `ctrl+y` in normal mode re-applies the last undone action (multi-level, same 10-entry cap as undo) by calling `git.RevertSHA` on the revert commit from the prior undo — reverting the revert re-applies the original change. `Model.redoStack` ([]string, capped at `undoStackCap`) mirrors `undoStack`: each successful undo pushes the revert commit's SHA onto `redoStack` (via `taskSavedMsg.redoSHA`); `redoCmd()` pops and reverts that SHA, then pushes the new SHA back onto `undoStack` via `taskSavedMsg.redoneSHA` (which preserves `redoStack`, unlike the plain `sha` field) so `u` → `ctrl+y` → `u` cycles symmetrically. `restoreRedoSHA` mirrors `restoreUndoSHA`: on redo failure the SHA is pushed back onto `redoStack` from the main loop. Standard redo semantics: any new mutation (non-empty `taskSavedMsg.sha`) clears `redoStack`, since the prior redo history is no longer valid. The former `clearUndo` flag is renamed to `clearHistory` and clears **both** stacks — used by remote sync, since a rebase may rewrite SHAs referenced in either stack. Empty-stack guard in `updateNormal` shows "nothing to redo" without calling the goroutine.
